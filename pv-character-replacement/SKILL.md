# PV 角色替换帧动画

把原 PV 的绘画语言、演出和曝光时间表迁移到新角色。目标是“同一段演出由另一个角色出演”，不是把精细立绘贴在原背景上。

逐帧分析、逐曝光合成，不等于每个视频帧都独立生图。高质量来自正确的独立绘稿、稳定的角色结构、可信的遮挡、完整可读的文字和合适的动作节奏；增加图片数量或输出帧率本身不能证明这些成立。

## 质量门槛与资料入口

开工、续作或准备终版时读 [references/production-playbook.md](references/production-playbook.md)：它定义试制、阶段门槛、记录、提速和终版条件。默认质量优先；用户明确选择完整草稿优先时，延期问题仍记未通过，不能改变终版标准。

- 分析、拆稿和时间轴：读 [references/analysis-and-timing.md](references/analysis-and-timing.md)。真实 PTS 优先于名义 fps。
- 逐稿提示词、关键姿势与参考分工：读 [references/prompt-patterns.md](references/prompt-patterns.md)。错误邻稿不得作为可靠锚点。
- 遮挡、人物 matte、文字、发束与衣料：读 [references/layers-and-continuity.md](references/layers-and-continuity.md)。检查生成图到最终编码的全过程。
- 检查、原速流畅度与反馈返工：读 [references/review-and-delivery.md](references/review-and-delivery.md)。技术通过和美术验收分开。
- 局部换人、按时间码返修或要求“其他不变”：读 [references/targeted-revisions.md](references/targeted-revisions.md)。先核对语义覆盖，再选择局部合成和编码路线。
- 出现反复错误时：读 [references/failure-patterns.md](references/failure-patterns.md)，按症状定位，不重复同一修法。
- 使用工具或适配新来源时：读 [references/script-map.md](references/script-map.md)，核对随包工具的支持范围和必须由当前项目提供的参数。

## 按实际复杂度安排制作

总视频帧数不等于需要生成的图片数。每支 PV 都重新测量以下维度，不套用另一工程的帧号、帧率、绘稿配额、周期或颜色阈值：

| 维度 | 决定什么 |
| --- | --- |
| 总解码帧数与真实 PTS | 分析、合成、编码的规模及精确时序 |
| 经核定的独立人物绘稿 | 必需生成/返修的动作与表情；候选和多版本另计 |
| 绘稿曝光及画面内实例 | 每次出现的位置、遮挡、重复与入退场 |
| 字幕/背景/特效相位 | 独立变化的合成和检查范围 |
| 遮挡、运动和画风风险 | 先试制哪些镜头、如何分批与验收 |

长持帧或重复循环多时，复用已核绘稿及人物层；短片若动作密集，仍需按真实变化充分拆稿。相机运动多不代表人物稿多，眼/手变化小也不代表可以合并。若人物确实连续变化，就按实际变化制作，不能为压低调用量把它强行变成几张循环立绘。

帧数增加时调整流式处理、磁盘缓存、依赖批次和检查点，不降低关键姿势或全片原速验收要求。批量大小按代表镜头的实测耗时、内存和返修风险决定，不预设通用的“每多少帧一稿”。具体分流见 [不同规模与时序的处理](references/production-playbook.md#不同规模与时序的处理)。

## 先确定制作约定

从用户现有要求与项目文件提取：原片/制作区间、替换哪些人物、角色版本与形态、采用的画风样例、声音、输出规格、最近认可版本、允许的运动处理与检查强度。只询问会阻塞制作的缺失项；其余按已知偏好推进。

- 默认 `strict_source`：保留原片独立绘稿及曝光边界，不自动改成固定 A/B 交替，也不把每个视频帧都重新生成。
- 用户需要长发等部位平顺转向时，可用 `adapted_motion`：新增模型绘制的过渡稿，保持镜头总长和主要拍点，明确记录曝光变化。没有这项授权时，先用同样曝光下幅度合适的重绘解决；需要增加过渡再说明具体取舍。
- 默认逐稿结构检查、整组连续性检查和实际速度对比。用户明确要求“先并发生成一轮、不返修”时照做，标注未审定，不把草稿算作已通过。
- 角色绘画默认由可用生图工具完成。若环境有 `imagegen` skill，遵循它的工具/保存流程；工具缺失时直说限制，保留分析及任务清单，不以程序画图冒充生图结果。调用量、并发和返修预算按用户要求或任务规模安排。

## 项目状态先落盘

开工建立或复用项目索引、可解析素材清单和当前状态入口，明确每个文件的用途、版本、依赖及采用关系。目录/脚本写职责与输入输出，批量图片用清单登记；不以聊天记忆或文件修改时间作为制作进度依据。默认可用 `PROJECT_INDEX.md`、`assets.json`、`STATUS.md`，已有等价文件时直接登记入口，不另建竞争的选稿表。

生图前登记任务；输出保存后立即记录路径、实测尺寸、SHA和真实事件。每次选稿、合成或验证完成后更新采用版本、检查范围、问题与下一步。续作或上下文压缩后，先读取这些入口并核对实际文件、选稿和未结束任务，再决定生成；未登记图片先恢复为待核候选，不直接重复生成或自动判通过。字段、写入顺序及恢复检查见 [项目状态与中断恢复](references/production-playbook.md#项目状态与中断恢复)。

## 1. 固定来源和角色基准

从同一份原片解码，记录画布、帧率/PTS、时长和声音；不用不同来源截图混合检测。可变帧率不能用平均帧率冒充原曝光表。

建立简短角色基准：正/侧/背视、脸和眼睛、手与袖口、主要饰品、轮廓与配色。检索资料时核对角色、版本及形态，区分官方设定、社区模型与二创，保存来源。用户提供的脸部参考优先解决身份细节，不自动提高全片渲染复杂度。

先试制项目实际存在的高风险类型，例如多人遮挡、近景手势、角色/背景近色、文字穿过衣服、标题与切镜相位。检查原稿、生成 PNG、新旧人物 matte、合成和最终编码，而不只批准立绘。试制通过的规则仍只覆盖已验证的镜头/文件/相位，不能据此宣布其他同色镜头通过。

先用少量具有代表性的镜头确定原 PV 的简化程度：轮廓、头身比、色块、线宽、阴影层数、饰品密度。已有认可样例时直接复用其风格。身份特征要稳定，原立绘的所有细节不必搬进简笔 PV。

## 2. 拆分语义与原片时间轴

分清人物绘稿变化、镜头变换和背景/歌词/粒子变化。每个镜头标出人物、衣物、道具、框内底色、遮挡物与特效的归属和层级；局部红色可能是头发，不能猜成桌面。

逐帧检测仅产生候选，再查阅原图与空间差值确认。睁闭眼、细小手势、衣褶、轮廓和加重描边都可能是独立绘稿。只有差异接近压缩噪声，且关键局部没有连贯形状变化时才合并。不要凭全画面平均差异、稀疏采样或“这段大概只有两张”决定。严格阈值可能把同稿的压缩副本拆成很多候选，不能直接按候选数批量调用生图；先核定真实绘稿。

保存原帧/PTS → 绘稿 ID 的明确曝光表，包含单帧转场和循环回到开头。分析、差值工具和时间轴格式见 [references/analysis-and-timing.md](references/analysis-and-timing.md)。

人物绘稿、相机、字幕换词、背景和特效各自保留时间表。字幕可能在人物持帧内部换词；复用人物绝不冻结这些独立层。没有脸的后脑、帽缘和退场残片也要逐个清点，不能用镜头族标签推断无人。

## 3. 给每张参考分配职责

每次 prompt 明确这些不同职责，不笼统写“严格参考所有图片”：

| 参考 | 决定什么 |
| --- | --- |
| 原 PV 当前目标绘稿 | 镜头、裁切、姿势、表情、视线、可见范围与遮挡 |
| 新角色设定 | 身份、固有发型/发色、服装结构、辨识特征 |
| 同镜头已认可的新角色绘稿 | 简化画风、比例、色彩、持续存在的发束与饰品 |
| 原作前后绘稿的实际二维差值图 | 哪里变化、方向/幅度、描边与褶皱变化 |
| 前后相邻的新绘稿 | 长发/衣物的连续运动、遮挡与发束连接 |

差值参考至少包含原 A/B 并排、实际 RGB 差值放大和双色轮廓叠图；必要时补眼、手、袖口与发梢局部放大。数字只能筛选，不能代替二维图。独立字幕和粒子应另看或在人物检测中遮掉。

实际查看每张参考与当前裁切。人物移动、全身转近景或背面转侧面后，重定局部框。已生成图如果含多余发束、错误领口、第三只手或错误姿势，删去其冲突整帧参考，换已核局部身份锚点；仅在 prompt 中写“不要继承”不足以阻止传播。

把变化逐项写进 prompt：眼睑/眉毛/嘴形、头发中段与发梢、两侧肩袖、袖口、衣摆、线条压力。已认可绘稿是连续性依据，不是冻结人物的模板。使用 [references/prompt-patterns.md](references/prompt-patterns.md) 中对应模板。

比例问题先区分身体姿态、衣料折叠与镜头缩放；下蹲不能把裙身整体压短。需要试长度时固定姿势出少量可辨方案，选定后核对站立→下蹲→回弹中的同一件衣服。具体约束见 [衣料与纯色检查](references/layers-and-continuity.md#衣料折叠与纯色检查)。

## 4. 按依赖批量生成

先完成身份和画风锚帧，再并发无依赖的镜头或关键姿势。相邻中间稿需要两个端点先就绪；不要把所有稿都从同一个极值母版独立生成。

复用实际重复的绘稿及其曝光，不复用表情/轮廓已经变化的帧。缓存通过的素材；局部修复只重新生成受影响的绘稿和合成区间；用户要求整帧时，每稿完整重绘，不生成小组件拼补。每次调用保存 prompt、参考顺序/职责、输出路径、采用或失败原因。

输出实测尺寸并保存工具原件与项目副本的 SHA-256，不能拿工具缩略显示尺寸充当实际 PNG 尺寸。中断后先核对已保存 job、版本、选稿和未完成门槛，不重跑完成稿。按实际事件区分参数失败、生图失败和账户限制；不静默更换模型或渠道。并行制作仅在用户或适用指令已授权时采用，且每个共享 cel 只有一个所有者。

需要过渡时，用相邻端点、原片差值及新绘稿的空间叠图约束中间位置。检查模型是否真的画在两个端点之间；“写了 halfway”不等于得到中间稿。若反复复制某个端点，减少冲突参考，改用明确局部编辑，再回到整组检查。

## 5. 连续性与分层合成

连续性既不是每帧换发型，也不是永久固定朝一边。持续发束、发长、体积、饰品和遮挡关系应可追踪；发根较稳，中段位移较小，发梢可有滞后。长发不能机械照搬原角色短发的左右极值。衣袖和衣摆应响应同一股风，幅度/相位可以不同。检查循环末帧 → 首帧。

默认未修改区域优先保留：以当前原视频帧为底图，只清除旧人物、恢复其露出的背景并合成新人物。字幕区在全部适用曝光中与新旧人物、抗锯齿边缘及实际编辑范围均不交叠时，直接保留该区域的原画面，不抠字、重建或让模型重画。每帧取对应原帧，不能冻结换词、背景或特效；交叠处才按实际遮挡分层处理。条件与保护区检查见 [未修改区域优先保留](references/layers-and-continuity.md#未修改区域优先保留)。

保留原框线、道具和独立特效，按原时间轴分层合成，不补画原构图外的脸、身体或手。优先限定区域和连通空背景掩膜，不能对全图相似颜色一删了之。

旧人物清除、新人物保留、独立前景恢复分别建检查依据；支持区内零误差可能只是遗漏的脸/袖口未被计入。中日文、标题和署名逐相位核对全文及出现时间；同色笔画不可观察时先找真实同句供体，取得所需重建授权后分别注册，不猜字或依赖 AI 重画文字。编码后还要检查可读对比，不以字芯 RGB 正确替代读得清。

默认不以光流、网格形变、镜像、morph 或交叉淡化冒充新的人物绘稿；用户明确允许近似时，记录使用范围。正常裁切、统一画布及源镜头确有的整层平移缩放要与非刚性人物变形区分。不要声称它们能代替衣褶、手指或发束重绘。

## 6. 检查与交付

按 [references/review-and-delivery.md](references/review-and-delivery.md) 检查三个层次：单稿结构、相邻及循环连续性、实际速度的原版/新版对比。手部、眼睛、缺失背景与特效必须与原帧对照；技术解码成功不是美术验收。

提供左原版/右新版的聚焦片段与完整目标区间，循环问题另给完整循环预览。核对帧数或 PTS、时长、音轨、切镜头和结尾。修复以最近有效版本为基线，保留其余部分及原有验收状态，避免合成长片时回退旧稿。用户时间码、动作名称与内部 cel 标签可能不一致；先把目标对应到实际镜头、表情阶段、重复实例及曝光，再在授权范围内修改，不仅凭文件名决定范围。

报告实际采用的绘稿数、曝光策略、检查范围和仍有差异。不要承诺 prompt 能精确锁住像素、空间差值必然被模型执行，或添加过渡后仍“逐帧曝光完全一致”。生成资产需保存到当前项目；仓库发布是独立操作，调用本 skill 不隐含上传原片、角色参考或个人文件。

随包 `probe_source.py` 捕获精确来源时序；`verify_encoded.py` 核验支持范围内的原 AAC 复制与视频编码，不能做美术判断。无原速观看或仍有字幕/旧人物残留等关键缺陷时，只能交付明确标记的草稿与缺陷清单，不能称高质量终版。详细命令和限制见脚本地图。
