# 局部换人与增量返修

用于已有成片上的时间码反馈、配角替换、表情修改，以及“其他地方不变”。目标是覆盖用户实际指定的内容，同时保住有效基线。一般制作与原速验收仍遵循 [制作流程](production-playbook.md) 和 [检查与交付](review-and-delivery.md)。

## 先确定语义覆盖

用户给的秒数可能取整，动作名称也未必对应工程中的精确 cel ID。先按实际 PTS 定位附近源帧，查当前成片和曝光表，找出镜头起止及相关表情阶段；不要用 `秒数 × 名义 fps` 或文件名字符串匹配直接定案。

从用户要求与源画面建立目标，再查当前选稿。为每个相关阶段记下：源帧 `[start,end)`、准确时间、目标人物/实例、当前资产、期望身份/表情、本次修改或保留及依据。例如同一次拥抱可能分为睁眼、闭眼、多个回声副本，而不是一个图片文件。

- 用户要求整个动作换对象时，核对动作内所有表情、重复副本和再次出现的曝光。
- 用户明确限定闭眼或某段时间时，只修改限定范围；邻接睁眼段仍应检查衔接，不能自行扩大修改。
- 用户指出漏改的前段时，以当前版补该段，保留已正确的后段；不从旧母版重建而回退已有修复。
- 同一素材在授权范围外也有曝光时，按曝光覆盖选择新版本，必要时分支资产；不全局替换共享 ID 后误改其他镜头。

把“应改曝光、实际采用新资产的曝光、应保留曝光”交叉核对。空目标、缺少阶段、范围外换稿都不能算完成。目标清单来自用户和源画面，不能用已修改结果反推一个天然全覆盖的目标。技术检查能证明视频完整，不能证明拥抱对象已经在每个目标阶段换对。

## 换身份时保留表演

配角身份、主角表情、姿势、原画面的表现方式分开约束。原配角是单色背影时，新配角的身份可由发型、帽形和服饰轮廓表达，保留原有单色处理；除非用户要求，不自动改成彩色正面立绘。

同姿势的睁眼/闭眼稿，可先核准双人构图，再以它作后续表情编辑的基线。旧稿仅负责当前目标表情，不让旧配角、旧比例重新混入；模板见 [双人镜头中的身份与表情分离](prompt-patterns.md#双人镜头中的身份与表情分离)。先对照源稿确认确实只有表情变化：源稿若另有手势、衣褶或轮廓差异，必须一并迁移，不能用换眼睛替代独立动作。

## 实测局部编辑的几何变化

“保持位置不变”的 prompt 不能保证像素锁定。实际解码 PNG 并记录尺寸、透明度和 SHA；相同画布尺寸也不证明主体大小相同。

1. 选择本次应保持的特征作配准依据，如未改的帽饰、衣纹或另一位人物。排除被修改的脸、透明底、字幕，以及源片的重复副本。
2. 可用 SIFT 配合 RANSAC 估计等比相似变换，记录变换方向、两端资产 SHA/尺寸、特征分布、内点数和重投影残差。特征集中在一个饰品上或内点数很大，仍不能证明整个人物对齐。
3. 同时查看原生尺寸叠图和对齐后残差。只校正非预期的整层画布/尺度漂移；局部比例、发束、手指变化须返修绘稿，不用非刚性变形压成“连续”。也不能对齐掉源片真实动作。
4. 明确原始 PNG、标准画布和源镜头三套坐标，记录裁切原点及缩放。不要把同一个表达式偏移应用两次。

若 `A` 把新 PNG 像素映射到旧 PNG 像素，`S_new`、`S_old` 各自把 PNG 映射到标准画布，则新标准画布到旧标准画布的矩阵为：

```text
B = S_old · A · inverse(S_new)
p_output = C_frame · B · p_new_canvas
```

使用齐次列向量；`C_frame` 包含该曝光实际需要的源相机/表达式变换，每项仅应用一次。经中间稿串联时，写清每个坐标端点，从右到左复合，并检查最终端到端结果。长配准链可能累积误差，优先保留稳定的标准锚点。估计失败或残差显示局部变形时标未配准，不把单位矩阵或近邻姿势静默当成功。

## 把“其他不变”写成可核验的约定

分别记录以下范围与证据，避免一句“不变”混淆不同保证：

| 对象 | 核验依据 |
| --- | --- |
| 用户授权修改的内容 | 语义覆盖表、人物/表情与源画面对照 |
| 无损合成中的保留区域 | 有效支持内逐帧源像素比较及边缘检查 |
| 实际重新编码区间 | 输出所依赖 GOP/随机访问边界，可能大于美术修改区间 |
| 未重编码视频 | 时间基换算后逐包对齐，比较载荷 SHA 和 PTS/DTS/时长；另查解码边界 |
| 原音频 | 原 AAC 载荷、配置、时戳、priming 和边界；不以“有声音”代替 |

完整 MP4 重新封装会改变容器字节，不能要求整文件 SHA 等于基线。视频包载荷相同也不独自证明解码相同：仍需正确的参考帧依赖、解码配置、色彩/宽高比元数据和边界核验。重新编码的保留画面可能有压缩差异，不能称像素或编码载荷完全不变。

### 选择增量编码路线

优先局部合成；是否能局部替换压缩包取决于已验证的编码结构，不是通用能力。以下简化路线仅适用于已核无 B 帧、配置一致且可证明独立边界的 H.264 主片；其他编码结构选择相应流程，不以总帧数决定能否拼包。

- **安全范围可证明时**：新段以独立可解码的 IDR 开始，接回点为基线中已确认的独立解码边界。无跨界依赖的情况下，修改起点本身不必原来就是关键帧；不能把“起止都必须是旧关键帧”作为普遍要求。
- **依赖不清或不满足时**：扩大到可证明安全的编码区间，未改帧取最新基线的解码结果；记录额外重编码范围及压缩差异。仍不支持时按已核时间轴重导，不用不安全拼包追求速度。
- 核对实际 B 帧/重排、封闭或开放 GOP、参考依赖与 SPS/PPS 等配置。容器的 `is_keyframe` 标记只是线索，不足以证明任意编码流能独立拼接；参数集匹配也是必要检查之一，不是全部证明。
- 新段的 MP4 可能把非零起始 PTS 归零。按源整数 tick 恢复 PTS 与 DTS，校验对应的帧数、展示顺序、包序列及尾曝光；无 B 帧时的“一帧一包、以 PTS 为键”实现不能迁移到未知结构。
- 保留色彩转换/范围、primaries/transfer/space、像素格式和 SAR/DAR。不能只写色彩标签，却用另一套 RGB→YUV 转换。
- 逐项计算修改范围证据，不能在报告里硬写 `unchanged=true`。报告绑定源、基线、输出、选稿和配方版本；继承基线的内容不自动继承更高的美术验收状态。

原 AAC 复制及截片遵循 [脚本地图](script-map.md) 的支持范围与最近音频 tick 规则。画面结束后才开始的额外音频包，与覆盖画面边界的最后完整包分清；不得为了容器时长数字好看而任意切包或改音频。

## 验收整个反馈对象

返修预览应覆盖用户实际指出的完整动作及相关表情切换；有必要时带上前后边界。不要只展示已经修好的后半段，给人整段已修的印象。片段标题/清单记录源区间，区分新增修改与沿用基线。

检查首末曝光、重复副本最密处、睁闭眼/姿势切换以及修改前后的实际编码帧。局部预览、主片、对照版分别检查自身时序与声音；对照直接复用完成主片，避免再次调用不同选稿的合成器。导出成功不代表实际观看过预览，原速美术检查仍单独记录。

将基线、语义修改范围、重编码范围、素材与配准、完整采用表、输出及验证报告写入当前工程的权威记录。把这些变化尽量作为参数传给已有导出流程；临时脚本或新版本文件只是执行入口，不能成为另一份与清单冲突的选稿依据。
